# PDF HWPX 골드셋과 실제 검색 평가

2026-10-17 재개 시 HWPX 파일 누락을 확인했다. 정상 v2는 원본 저장본의 기존 SHA-256 일치로 복원했고 과거 v1 바이트는 미복원이다. 현재 부정 회귀는 별도 procedure-recovery-invalid.hwpx(PNG CRC 오류)를 사용하며 옛 v1과 같다고 주장하지 않는다. manifest/과거 보고는 보존한다. hwpx-recovery.json과 restore_synthetic_fixtures.py로 검토된 합성2개만 덮어쓰기 없이 복구한다. ## Phase 2B 합성 부분표본 추가

tests/fixtures/synthetic/phase2b_pdf.py는 폰트 파일을 포함하지 않는 순수 Python 합성2페이지 PDF 생성기다. 명시 좌표 문단·2×2 선 표·병합 변형을 시험하며 PDF10/HWPX17개 블록의 저장/원문 재해결 증거는 outputs/phase2b/SAMPLE_EXTRACTION.json이다. HWPX는 기존 v2 원본을 보존하고 메모리 내 제목/병합/spine 변형만 사용했다. PDF2페이지는 Poppler 렌더를 확인했으나 한컴 HWPX 렌더는 NOT_RUN이다. 기대값은 코드에 명시한 합성 개발 표본이며 독립 검토자가 동결한 전체 골드셋이 아니다. 실제 공개 corpus 추가·대표 한국어 PDF/복잡 레이아웃·기존 문서5종/캡처20/질의40/절차10 목표는 별도로 남는다.

상태: bootstrap v0.1 설계/합성 부분표본. 전체 대표 corpus·정량 품질 합격은 아직 아니다. 기존 TEST_PLAN의 문서5종 이상·캡처20장 이상·질의40개 이상·절차10개 이상 목표를 축소하지 않는다. 직접 만든 단순 HWPX/PDF는 도구/계약 검사용이며 기관 일반화와 복잡 레이아웃 대표성은 미검증이다.

## 자료 구성과 사람이 확정할 정답

| 묶음 | 자료·변형 | 확인할 요소 |
|---|---|---|
| 기준 텍스트 | PDF/HWPX 각각 공개/합성 정상 파일 | 문단·표·그림·원문 페이지/bbox 또는 XML 경로·시각 순서 |
| 기관 A/B | 같은 용어·서로 다른 기한/서식·효력시점 | 기관 격리·버전·충돌, 임의 법적 우선순위 금지 |
| 업무 일반화 | 코드/튜닝에서 보지 않은 기관 업무 1종 이상 | 새 업무·단계·순서·서식 연결, 업무별 코드 수정 0 |
| 이미지 | 작은 글씨·저해상도·문단 사이 캡처20장 이상 | OCR/UI 요소·관찰 설명·실제 그림 근거, 없는 행동 생성 금지 |
| 안전/갱신 | 없음·상충·옛 버전·등록 해제·손상·문서 지시 공격 | 미확인·충돌·해제 차단·복구·프롬프트 인젝션 |

각 자료는 공개 URL/출처 또는 합성 생성기·버전·라이선스·SHA-256·tenant/document/version·적용시점·파서/렌더 버전을 manifest에 기록한다. 원본을 읽기 전용으로 보존하고 기대값은 사람 검토자/일시·근거 위치/인용·정답 단계/간선/조건/서식을 기록한다. 이번 HWPX는 python-hwpx6.8.0 생성·저장/재열기 검증을 거친 완전한 합성 패키지이며 한컴 렌더 검증은 미실행이다. 그림은 구조용 픽셀이므로 OCR 성능 표본이 아니다.

개발/튜닝 자료와 최종 holdout 자료를 문서 단위로 분리하고 같은 문서의 다른 chunk/버전이 양쪽에 새지 않게 한다. 공개자료라도 개인정보가 섞였으면 사용하지 않는다. 불확실한 출처는 확보 완료로 표시하지 않는다. 현재 bootstrap subset은 expected 값 작성법과 검증 도구 계약만 검토한다.

## 실제 임베딩 검색 평가 확정 방법

1. 승인된 실제 embedding provider/model/version/dimension/정규화/cosine metric/구조 chunk 버전을 고정한다. 비용 발생 전 corpus·질의·token/금액 상한 승인을 받는다. 수동 벡터로 실제 의미검색을 대체하지 않는다.
2. 기관 멤버십·공통팩 허용·활성 버전·효력시점 필터를 적용한 keyword-only, vector-only, hybrid를 같은 질의로 비교한다. 필터가 다른 결과를 단순 품질 비교하지 않는다.
3. 답변 가능한 질문은 Hit@5=정답 근거가 하나 이상 포함된 질문/답변 가능 질문으로 계산하고 기존 목표90%를 유지한다. 추가 Recall@5는 질의별 정답 중 검색된 비율의 평균, MRR@5는 첫 정답 역순위 평균이다. 중복 ID는 오류로 처리한다.
4. 정보 없음 질의는 품질 분모에서 분리해 false-positive/정답 없음 처리·무근거 단정 0건을 평가한다. 타기관/비활성/해제 ID가 검색되면 순위 점수와 무관하게 안전성 FAIL이다.
5. 정답 원문을 가리키는 chunk→element 매핑과 원문 렌더/XML 앵커를 사람이 대조한다. 실제 주장 의미 일치는 별도 평가다. 질의·표본수·분자/분모·실패사례·모델/인덱스 세대·지연p50/p95·자원·비용을 함께 보고한다.
6. embedding 교체는 별도 차원/세대 색인으로 재구축하고 혼합 금지·전환/롤백을 시험한다. 스코어러 단위시험 PASS와 실제 retrieval 품질 PASS를 분리한다.

평가 도구 입력은 queries의 expected element ID/권한 범위와 results의 순위 element ID다. actual model metadata가 없는 자료는 명시적 metric-fixture 모드에서만 계산하며 이를 실 embedding 평가로 제출하지 않는다. 전체 대표셋 확정과 실제 검색은 G1-B, 전체 동결 골드셋·증거 패키지는 G1-D다.

정상 합성 HWPX의 현재 기준은 procedure-v2.hwpx다. v1은 내장 PNG CRC 오류가 발견돼 이미지 무결성 FAIL의 negative fixture로 보존했다. v2에서는 PNG chunk CRC도 검증한다. 라이브러리 XML 구조 검사와 asset 참조 검사만으로 정상 이미지 파일까지 입증됐다고 하지 않는다.
