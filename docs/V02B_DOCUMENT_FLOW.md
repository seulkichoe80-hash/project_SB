# v0.2-B 문서 처리·활성화 동선

## 범위와 계약

FR-01/09/14/15/18, NFR-01/02/04/05, WEB-02/04/05/06의 관리자 문서 동선을 개선한다. v0.2-A 로컬 커밋 `809a2dd3599bb9d0d1610f13a2d1bc439d30d9ef`를 보존하고 `feat/v02b-document-flow`에서 작업한다. 기본 인증 차단, API·DB·파서·업무절차 엔진은 변경하지 않는다.

등록 성공 후 반환된 문서·버전을 기존 상세 API에서 다시 확인하여 바로 연다. 다음 작업 영역은 등록, 원문 처리, 파싱, 청킹, 현재 활성 버전을 표시한다. 완료를 추정하거나 등록만으로 활성화하지 않는다. 파싱·청킹 실패는 각각 재시도와 상태 확인을 제공한다. 자동 polling은 추가하지 않고 사용자가 새로고침한다.

## 기존 API 재사용

- `GET /documents?active_only=false`, `GET /documents/{document_id}/versions/{version_id}`: 기관 내 문서 목록·버전 상태.
- 기존 등록 POST: 공개·합성 자료 확인 및 원본 보존 계약 유지.
- `GET .../parsing`, `POST .../parsing/retry`: 파싱 상태와 재시도.
- `POST .../chunk-jobs`, `GET .../chunk-jobs/{job_id}`, `POST .../chunk-jobs/{job_id}/retry`: 청킹 요청·멱등 복구·상태·재시도.
- `POST .../activate`: 명시적 관리자 활성화.
- 기존 workflow 조회/작업/EvidenceRef API: 이동 후 기존 화면에서 사용.

청킹 작업 목록 API는 없다. 새로고침·재방문 후에는 작업 ID를 미확인으로 표시하며, 관리자가 누르는 ‘청킹 요청·상태 확인’ POST의 멱등 응답으로 현재 기본 설정 작업 ID를 얻는다. 이 동작은 실제 작업이 없으면 새 청킹 작업을 등록할 수 있음을 안내한다. localStorage/sessionStorage에 작업 ID·인증정보·원문을 저장하지 않는다.

## 활성화 안전성

버전 등록 상태·원문 처리 완료·파싱 완료·청킹 완료, 버전/parse job/parse attempt 일치가 확인된 비활성 버전에서만 활성화 버튼을 제공한다. reader에게 처리·활성화·관리자 workflow 이동 버튼을 제공하지 않는다.

확인창은 문서명·선택 버전·현재 활성 버전·영향·공식 승인과의 차이를 보여준다. 취소/Escape는 요청하지 않으며, 확인 중에는 중복 제출을 차단한다. 요청 전 detail/parsing/chunk status/list를 다시 조회하고 해시·revision·현재 활성 버전·완료·원문 처리 세대 조건이 바뀌면 POST하지 않는다. POST는 기존 동일 출처 세션 쿠키와 X-CSRF-Token을 사용한다. Origin과 manager 권한·기관·등록 상태·처리 준비·원본 해시는 기존 서버에서 재검증한다.

성공 응답 뒤 detail과 list를 다시 조회하여 선택 버전의 활성 상태를 확인한다. 실패·409·네트워크 오류·재조회 실패를 활성화 성공으로 표시하지 않는다. 모호한 실패는 서버가 이미 처리했을 수도 있으므로 사용자에게 재조회가 필요함을 안내한다. 단계 변경·기관/사용자/역할 변경·페이지 이탈은 요청을 취소하고 늦은 응답을 폐기한다. 요청 취소가 서버에서 이미 실행된 활성화를 취소한다는 의미는 아니다.

기존 API에는 expected-active-version/If-Match 등 비교 후 교환 계약이 없다. 사전 조회 이후 POST 사이의 동시 관리자 변경을 원자적으로 차단하지 못한다. 서버는 트랜잭션 단위로 유효한 버전 활성화를 처리하지만 최종 활성 버전은 나중 요청에 따라 달라질 수 있다. 이번에는 API 변경 없이 사전 비교·사후 재조회로 보완한다.

## 업무절차 화면 이동

활성 버전에는 재활성화 버튼을 표시하지 않고 ‘업무절차 후보 검토’ 링크를 제공한다. `#/workflows?document=...&version=...`에는 opaque 문서·버전 ID만 전달한다. 이 값은 신뢰하지 않으며, 서버가 현재 사용자에게 반환한 기관·등록·활성·완료 목록에서 정확한 쌍을 찾는다. 확인되지 않은 주소는 다른 문서로 자동 대체하지 않고 오류를 표시한다. 기존 workflow API에서도 기관·활성 버전·세대와 근거를 다시 검사한다. 자동 추출·의미 검증·공식 승인을 수행하는 링크가 아니다.

## 검증

타입/빌드, 신규 `check_v02b_ui.cjs`, 실제 loopback `check_v02b_http.cjs`, 기존 UI·권한·근거 회귀를 실행한다. 테스트는 명시적 모의 인증과 기존 합성 PDF/HWPX만 사용한다. HTTP 통합은 실제 서버·독립 worker·세션·CSRF/Origin을 사용하고, 지연/네트워크 오류 조합은 Chromium 모의 응답으로 별도 검증한다. 실제 Supabase·LLM·임베딩·배포는 실행하지 않는다. 실행 결과는 `outputs/V02B_REPORT.md`에 기록한다.
