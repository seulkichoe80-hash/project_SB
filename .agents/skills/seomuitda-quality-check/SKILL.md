# 서무ITDA 단계별 품질검증

프로젝트 루트는 이 파일 디렉터리의 `../../..`이다. 루트 AGENTS.md·PRD.md·TASKS.md·ARCHITECTURE.md·TEST_PLAN.md와 docs/G1_GATES.md를 기준으로 검증한다. 보안 규칙·범위·수치를 여기에 복제하지 않는다.

## 입력과 검사 범위

검증 대상 변경/Phase, 관련 FR/NFR/WEB, 실행환경·배포 단계, 수정 파일, 이미 실행한 시험 결과를 확인한다. 유료 호출/자원 생성/공개 배포의 실제 승인 범위와 미실행 이유도 확인한다. 코드가 없으면 문서 게이트만 평가하고 기능 시험은 NOT_RUN으로 둔다. 동일 변경/환경의 유효한 결과를 재사용할 수 있으나 새 영향은 다시 검증한다.

## 반복 절차

1. PRD의 대상 FR/NFR/WEB에서 TASKS의 작업·게이트, TEST_PLAN의 시험 행으로 추적한다. 누락 ID·범위 변경·조건부 기능의 잘못된 완료 표시를 찾는다. 문서 링크와 기술 채택 상태도 대조한다.
2. TEST_PLAN의 데이터/기대값/실행 기록 계약을 확인하고 해당 기능 시험을 실행한다. 명령이 아직 정의되지 않았으면 추측해서 통과 처리하지 말고 미실행 사유와 필요한 환경을 기록한다.
3. 대표 답변·지도 노드와 관계·추천·그림 설명·채택된 초안 규정 필드에서 근거 링크를 실제로 연다. 문서/버전/기관/위치와 주장 일치, 원문/OCR/AI/사용자 입력 구분을 확인한다. 근거 없는 결과의 억제와 충돌 표시도 검사한다.
4. 원본 해시를 변경 전후 비교하고 등록 해제·교체 후 검색/대화 캐시/지도/추천의 옛 내용 차단과 기관/역할 교차 접근을 시험한다. TEST_PLAN의 변경 영향 규칙에 따라 회귀 범위를 확장한다.
5. 단계 전환은 docs/G1_GATES.md의 A/B/C/D 분류와 TASKS의 해당 G 게이트와 TEST_PLAN의 전체 필수/채택 조건부 시험을 대조한다. 모델/임베딩 변경은 실제 연결과 재색인 결과를 별도로 확인하고 mock 실증과 혼동하지 않는다.
6. TEST_PLAN의 WEB 시험을 따라 HTTPS·정확 CORS·로그인/역할/기관 API 우회·시크릿/번들·요청/비용 제한, 재시작/재배포 영속성·DB/객체 복원을 확인한다. 배포가 미승인/미실행이면 해당 결과를 BLOCKED/NOT_RUN으로 둔다.
7. 제출 후보에서는 일반 사용자의 PC 브라우저 무설치 흐름과 평가자의 독립 소스 실행을 별도로 확인한다. URL·실제 명령·키 입력 위치·샘플·제약·플랜/콜드스타트·규격/라이선스가 안내서와 일치하는지 대조한다. 원격/접수는 승인된 실제 증거가 있을 때만 완료로 기록한다.

## 결과 기록과 중단 조건

결과는 검증 범위, 환경/자료/모델/코드 버전, 실행 명령, 통과/실패/미실행, 정량 분자·분모, 실패 근거, 조치와 재시험, 다음 게이트 가능 여부로 남긴다. 기존 결과 파일을 덮어쓰지 않고 새 실행 기록을 추가한다. 문서/로컬 준비와 실제 제출 상태를 구분한다.

JSON 스키마/근거 재해결/의미 일치, HWPX 논리/시각 순서, 모의/실제 모델, 기존 PASS/신규 미검증을 구별한다. 과거 보고와 증거는 수정하지 않고 현재 결과를 추가한다. 내부망/GPU/Docker는 현재 MVP 비대상이며 검사 실패를 PASS로 바꾸지 않는다.

안전성 게이트 실패 또는 대상 게이트 미충족이면 다음 단계 완료를 선언하지 않는다. 수정 가능한 범위는 기존 승인 안에서 보완 후 재시험하고 환경/권한 부재는 필요한 조건과 담당 확인사항을 보고한다. 이 Skill은 배포·push·전송·제출 권한을 부여하지 않는다.
