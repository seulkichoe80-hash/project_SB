# 서무ITDA 단계별 품질검증

프로젝트 루트는 이 파일 디렉터리의 `../../..`이다. [AGENTS](../../../AGENTS.md)를 적용하고 관련 요구사항·계약만 확인한다. 실행 시점·범위·변경 영향·결과 재사용은 [TEST_PLAN](../../../TEST_PLAN.md#테스트-실행-시점과-범위)이 단일 기준이다. 보안 규칙·시험 목록·수치를 복제하지 않는다.

## 검증 수준 선택

| 수준 | 호출 조건과 적용 범위 |
|---|---|
| Feature Gate | 기능 완료 시 TEST_PLAN의 영향 통합시험·해당 핵심 안전성 회귀를 확인 |
| Phase Gate | 단계 완료 시 전체 회귀 결과와 [TASKS](../../../TASKS.md)·[G1 A/B/C/D](../../../docs/G1_GATES.md)의 해당 게이트를 대조 |
| Release Gate | 배포·제출 후보의 전체 검증. 실행 범위는 TEST_PLAN, 제출 조건은 TASKS를 따르고 실제 외부 작업은 별도 승인 확인 |
| Read-only Review | 문서·기존 증거만 검토. 테스트·앱 실행·파일/캐시/로그 변경 없이 답변으로 결과와 추가 검증 필요사항 보고 |

명시된 수준이 없으면 현재 요청의 완료 단위에 맞춰 선택하고 보고한다. 개발 중 단순 수정은 TEST_PLAN의 단위 테스트 기준을 따르며 전체 Gate를 매번 호출하지 않는다. 읽기 전용 요청은 다른 수준의 실행 절차로 확대하지 않는다.

## 반복 절차

1. 선택 수준, 변경 파일, 관련 FR/NFR/WEB·계약·시험 행을 연결한다. 문서 링크·요구사항 추적성과 조건부 기능 상태를 확인한다. 전체 기준 문서 재독 조건은 AGENTS를 따른다.
2. TEST_PLAN에 따라 필요한 시험을 실행하거나 재사용 조건과 기존 실행 증거를 확인한다. 코드·fixture·환경·잠금파일·설정·명령·검증 범위의 비교 근거를 남긴다. 변경 영향은 재시험하며 Phase Gate의 전체 회귀는 생략하지 않는다.
3. 대상 기능의 실제 원문 근거를 열어 기관·문서·버전·앵커·주장 일치와 원문/OCR/AI/사용자 입력 구분을 확인한다. 구조 유효성과 의미 일치, HWPX 논리 순서와 시각 순서, mock과 실제 모델을 구별한다. Read-only Review에서는 기존 증거의 검증 범위만 확인한다.
4. 대상 Gate 필수 항목의 누락과 안전성 실패를 확인한다. 관련 없는 미구현·미승인 항목은 기존 NOT_RUN/BLOCKED 기록을 참조하고 상태를 유지한다. 같은 미검증 목록을 매번 새로 작성하지 않으며 대상 필수 시험의 미실행을 PASS로 바꾸지 않는다.

## 결과와 중단 조건

선택 수준·변경 범위·실행/재사용 근거·통과/실패/미실행·남은 위험·다음 게이트 가능 여부를 요약한다. 시험 기록의 필드는 TEST_PLAN을 따르고 상세 실행 증거는 공통 기록을 참조한다. 실행 기록은 새 파일로 추가하고 과거 보고·증거를 덮어쓰지 않는다. Read-only Review는 파일을 생성하지 않는다.

안전성 게이트 실패 또는 대상 게이트 미충족이면 다음 단계 완료를 선언하지 않는다. 근거·권한·기관 격리·원본 불변·활성 버전/등록 해제·실패 복구의 실패는 기능 확대를 중단하고 승인된 범위에서 수정·재시험한다. 환경·권한 부재는 필요한 조건과 담당 확인사항을 보고한다. 문서/로컬 준비와 실제 배포·제출은 구분하며 이 Skill은 유료 호출·자원 생성·배포·push·전송·제출 권한을 부여하지 않는다.
